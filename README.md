# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
В приложении используются две сущности, которые описывают данные, — товар и покупатель.

#### Интерфейс IProduct
Интерфейс IProduct описывает структуру данных товара, который отображается в каталоге интернет-магазина, в карточке товара и в корзине.

```TS
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

Поля интерфейса:

`id: string` — уникальный идентификатор товара. Используется для поиска товара в списке, добавления в корзину и работы с конкретной карточкой.

`description: string` — текстовое описание товара, которое отображается при подробном просмотре.

`image: string` — ссылка на изображение товара. Используется для вывода картинки в каталоге и модальном окне товара.

`title: string` — название товара. Отображается в карточке товара и корзине.

`category: string` — категория товара. Используется для группировки, стилизации или дополнительного отображения информации о товаре.

`price: number | null` — цена товара. Может содержать значение null, если товар недоступен для покупки или цена отсутствует.

#### Интерфейс IBuyer
Интерфейс IBuyer описывает данные покупателя, которые пользователь вводит при оформлении заказа.

```TS
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

Поля интерфейса:

`payment: TPayment` — способ оплаты, выбранный пользователем. Поле хранит одно из допустимых значений типа TPayment.

`email: string` — адрес электронной почты покупателя. Используется для связи и отправки информации о заказе.

`phone: string` — контактный номер телефона покупателя.

`address: string` — адрес доставки заказа.

#### Тип TPayment
Тип TPayment описывает допустимые способы оплаты заказа в приложении.

```TS
type TPayment = 'online' | 'cash' | '';
```

Возможные значения:

`'online'` — онлайн-оплата банковской картой или иным электронным способом.

`'cash'` — оплата при получении заказа.

`''` — тип оплаты еще не выбран.

### Модели данных

#### Класс ProductCatalog
Класс `ProductCatalog` отвечает за хранение и предоставление данных о товарах, доступных в приложении.

Конструктор класса не принимает параметров.

Поля класса:

`products: IProduct[]` — массив всех товаров каталога. Хранит список товаров, доступных для отображения и покупки.

`selectedProduct: IProduct | null` — выбранный товар. Используется для хранения карточки товара, которую пользователь открыл для подробного просмотра.

Методы класса:

`setProducts(products: IProduct[]): void` — сохраняет массив товаров, переданный в параметре, в модель каталога.

`getProducts(): IProduct[]` — возвращает массив всех товаров.

`getProductById(id: string): IProduct | undefined` — возвращает товар по его идентификатору или `undefined`, если товар не найден.

`setSelectedProduct(product: IProduct): void` — сохраняет товар для подробного отображения.

`getSelectedProduct(): IProduct | null` — возвращает товар, выбранный для подробного просмотра.

#### Класс Cart

Класс `Cart` отвечает за хранение товаров, которые пользователь добавил в корзину.

Конструктор класса не принимает параметров.

Поля класса:

`selectedProducts: IProduct[]` — массив товаров, добавленных пользователем в корзину.

Методы класса:

`getProducts(): IProduct[]` — возвращает массив товаров, которые пользователь добавил в корзину.

`addProduct(product: IProduct): void` — добавляет товар в корзину.

`removeProduct(product: IProduct): void` — удаляет товар из корзины.

`clear(): void` — полностью очищает корзину.

`getTotalPrice(): number` — возвращает суммарную стоимость всех товаров в корзине.

`getCount(): number` — возвращает количество товаров в корзине.

`hasProduct(id: string): boolean` — проверяет, есть ли товар с указанным идентификатором в корзине.

#### Класс Buyer
Класс `Buyer` отвечает за хранение, получение, очистку и проверку данных покупателя, которые вводятся при оформлении заказа.

Конструктор класса не принимает параметров.

Поля класса:

`buyerData: IBuyer` — объект с данными покупателя. Хранит выбранный способ оплаты, адрес доставки, номер телефона и адрес электронной почты пользователя.

Методы класса:

`setData(data: Partial<IBuyer>): void` — сохраняет данные покупателя в модель. Метод принимает объект, который может содержать одно поле или сразу несколько полей. При вызове обновляются только те значения, которые были переданы в параметре. Остальные ранее сохранённые данные не изменяются.

`getData(): IBuyer` — возвращает все данные покупателя, сохранённые в модели.

`clear(): void` — очищает данные покупателя.

`validate(): Partial<Record<keyof IBuyer, string>>` — выполняет проверку данных покупателя. Если какое-либо поле не заполнено, в возвращаемый объект добавляется свойство с названием этого поля и текстом ошибки.

### Слой коммуникации

#### Интерфейс IProductResponse
Интерфейс `IProductResponse` описывает объект, который приложение получает с сервера при запросе списка товаров.

```TS
interface IProductResponse {
  total: number;
  items: IProduct[];
}
```

Поля интерфейса:

`total: number` — общее количество товаров, доступных на сервере.

`items: IProduct[]` — массив товаров, полученных с сервера.

#### Интерфейс IOrder
Интерфейс `IOrder` описывает объект заказа, который приложение отправляет на сервер. Этот тип расширяет интерфейс IBuyer и дополняет его данными о составе заказа.

```TS
interface IOrder extends IBuyer {
  total: number;
  items: string[];
}
```

Поля интерфейса:

`payment: TPayment` — выбранный способ оплаты.

`email: string` — адрес электронной почты покупателя.

`phone: string` — контактный номер телефона покупателя.

`address: string ` — адрес доставки.

`total: number` — итоговая стоимость заказа.

`items: string[]` — массив идентификаторов товаров, добавленных в заказ.

#### Интерфейс IOrderResponse
Интерфейс `IOrderResponse` описывает объект, который сервер возвращает после успешного оформления заказа.

```TS
interface IOrderResponse {
    id: string;
    total: number;
}
```

Поля интерфейса:

`id: string` — уникальный идентификатор оформленного заказа.

`total: number` — итоговая стоимость подтверждённого заказа.

#### Класс WebLarekApi
Класс `WebLarekApi` отвечает за взаимодействие приложения с сервером интернет-магазина. Класс использует композицию: в конструктор передаётся объект, реализующий интерфейс `IApi`, после чего методы класса используют его методы `get` и `post` для выполнения HTTP-запросов.

Конструктор класса:

`constructor(api: IApi)` — принимает объект, соответствующий интерфейсу `IApi`, который используется для выполнения запросов к серверу.

Поля класса:

`api: IApi` — объект для выполнения HTTP-запросов к серверу.

Методы класса:

`getProducts(): Promise<IProductResponse>` — выполняет GET-запрос на эндпоинт `/product/` и возвращает объект с данными каталога товаров, полученный с сервера.

`createOrder(order: IOrder): Promise<IOrderResponse>` — выполняет POST-запрос на эндпоинт `/order/`, отправляет данные заказа на сервер и возвращает объект, содержащий подтверждение заказа и итоговую сумму.

### События приложения

В приложении используется событийно-ориентированный подход. События генерируются как в моделях данных, так и в компонентах представления. Презентер подписывается на эти события и обрабатывает их в соответствии с логикой приложения.

#### События модели данных

Событие `catalog:changed` — генерируется моделью `ProductCatalog` при изменении списка товаров каталога. Используется для перерисовки каталога товаров на главной странице.

Событие `selectedProduct:changed` — генерируется моделью `ProductCatalog` при изменении выбранного товара для просмотра. Используется для открытия модального окна с подробной информацией о товаре.

Событие `basket:changed` — генерируется моделью `Cart` при изменении содержимого корзины. Используется для обновления счётчика товаров в шапке сайта, общей стоимости и содержимого корзины.

Событие `buyer:changed` — генерируется моделью `Buyer` при изменении данных покупателя. Используется для обновления состояния форм оформления заказа.

#### События представлений

Событие `card:select` — генерируется при выборе карточки товара в каталоге. Используется для сохранения выбранного товара в модель и открытия его подробного просмотра.

Событие `card:toggle` — генерируется при нажатии на кнопку покупки или удаления товара из корзины в карточке подробного просмотра. Используется для добавления товара в корзину или удаления его из корзины.

Событие `basket:open` — генерируется при нажатии на кнопку корзины в шапке сайта. Используется для открытия модального окна корзины.

Событие `basket:cardDelete` — генерируется при нажатии на кнопку удаления товара из корзины. Используется для удаления выбранного товара из модели корзины.

Событие `order:open` — генерируется при нажатии на кнопку оформления заказа в корзине. Используется для открытия первого шага формы оформления заказа.

Событие `order.payment:changed` — генерируется при выборе способа оплаты в первой форме оформления заказа. Используется для обновления данных покупателя.

Событие `order.address:changed` — генерируется при изменении адреса доставки в первой форме оформления заказа. Используется для обновления данных покупателя.

Событие `order:submit` — генерируется при отправке первого шага формы оформления заказа. Используется для перехода ко второму шагу оформления заказа.

Событие `contacts.email:changed` — генерируется при изменении email во второй форме оформления заказа. Используется для обновления данных покупателя.

Событие `contacts.phone:changed` — генерируется при изменении телефона во второй форме оформления заказа. Используется для обновления данных покупателя.

Событие `contacts:submit` — генерируется при отправке второго шага формы оформления заказа. Используется для отправки заказа на сервер.

Событие `modal:close` — генерируется при закрытии модального окна:
- при нажатии на кнопку-крестик;
- при клике по оверлею;
- при нажатии на кнопку в окне успешного оформления заказа.

### Презентер

В приложении реализован один презентер, так как приложение состоит из одной страницы. Роль презентера выполняет файл `src/main.ts`.

Презентер связывает между собой модели данных, компоненты представления и коммуникационный слой.  
Он подписывается на события, генерируемые моделями и представлениями, и в ответ вызывает методы моделей или обновляет компоненты интерфейса.

#### Ответственность презентера

Презентер отвечает за следующие сценарии приложения:

- получение списка товаров с сервера;
- сохранение товаров в модель каталога;
- отображение каталога товаров на главной странице;
- открытие модального окна с подробной карточкой товара;
- добавление и удаление товаров из корзины;
- обновление счётчика корзины и содержимого корзины;
- открытие корзины в модальном окне;
- открытие пошаговых форм оформления заказа;
- обновление модели покупателя при вводе данных в формы;
- переход между шагами оформления заказа;
- отправку заказа на сервер;
- отображение окна успешного оформления заказа;
- очистку корзины и данных покупателя после успешной оплаты.
